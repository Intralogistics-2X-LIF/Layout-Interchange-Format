Part or all of these changenotes and their described and referenced objects, section numbers, or section names may become out of date upon any new release of the LIF, major, minor, or patch.

# Primary Changes
These are the primary new features of the LIF.

## Removal of Uni-directionality Constraint of LIF Transfers
The LIF no longer explicitly states that it is a vehicle provider to traffic control provider definition. It is now a party-agnostic mere declarative definition of the navigation graph which a mobile robot supports, and the information required by a traffic controller to supply VDA 5050 orders to the mobile robot. The text in section 7 has been updated accordingly.

This means that any party may create and supply a LIF to other parties, be they design tooling providers, mobile robot providers, fleet control providers, integrators, or whomever else.

## New Near-Root Object: Origin
Previously: LIFs had Layouts. Now: LIFs have Origins have Layouts. Two layouts sharing an origin explicitly confirms that they share a coordinate origin (including rotation and scale) and that their coordinate systems are aligned (and therefore the two Layouts may directly overlap). See new section 8.3.3.1 Best Practices for Defining an Origin for more information.

## LIF 2.0's Support of Different VDA 5050 Versions
While LIF 2.0 has been changed in many ways (see some secondary changes below) to match VDA 5050 version 3.0's new nomenclature, fields, and so forth, backwards compatibility of LIF 2.0 with VDA 5050 2.1 was preserved.

Some LIF fields have notes to a traffic control provider about which fields in the LIF can be used in a VDA 5050 2.1 context.
