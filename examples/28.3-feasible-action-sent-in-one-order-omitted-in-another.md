## 28.3 Feasible Action Sent in One Order, Omitted in Another

A node where charging is optional rather than mandatory, illustrated by two orders valid against the Base LIF above: one requests it for a low battery state, the other skips it for a pass-through visit.

Order A (nodes array, battery low, charging requested at N2):
```json
{
    "nodes": [
        {
            "nodeId": "N2",
            "sequenceId": 4,
            "released": true,
            "actions": [
                {
                    "actionId": "charge_001",
                    "actionType": "startCharging",
                    "blockingType": "SOFT"
                }
            ]
        }
    ]
}
```

Order B (nodes array, battery fine, N2 only used as a pass-through):
```json
{
    "nodes": [
        {
            "nodeId": "N2",
            "sequenceId": 4,
            "released": true,
            "actions": []
        }
    ]
}
```
